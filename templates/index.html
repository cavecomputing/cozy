          Prompt Builder syntax

          You don't need to change anything here. The default template already produces a sensible system message for every character. Only edit the template if you specifically want to change how the prompt is assembled — re-order sections, rename labels, drop a section entirely, add custom instructions, etc.

          The textarea is a template. When a message is sent, it's resolved into the system message that goes to the model. Whatever you write here, character data and persona data is folded into, gets sent.

          Variables — {{name}}

          Each {{name}} is replaced with the corresponding value at send time.

          You are {{char}}, in conversation with {{user}}.
{{description}}

          Empty variables resolve to an empty string. See the Available variables list under the textarea for the full set.

          Conditional blocks — {{#name}}…{{/name}}

          A conditional block is a fence around a chunk of template. The fence has an opening tag {{#name}} and a matching closing tag {{/name}} — the names must match on both sides.

          The rule: if the variable named in the fence is empty (or only whitespace), the entire fenced section is deleted from the output — including any labels, headers, and punctuation you wrote inside. If the variable has content, the fence tags themselves disappear and the inside is kept.

          Why it exists

          Without a conditional, this template:

          [Scenario]
{{scenario}}

          …always emits the [Scenario] line — even when the character has no scenario set. You'd get a header with nothing under it. The model might think you forgot something.

          With a conditional

          {{#scenario}}[Scenario]
{{scenario}}{{/scenario}}

          If scenario is set to "Lost in a forest" — fence tags vanish, the inside renders normally:

          [Scenario]
Lost in a forest

          If scenario is empty — the whole fenced block is removed, header and all. No orphan [Scenario] line.

          What counts as "empty"

          • null / undefined — empty
          • "" (empty string) — empty
          • " " (only spaces or newlines) — empty
          • Anything with real characters — not empty, block is kept

          What can go inside the fence

          Anything you want — labels, brackets, multi-line text, even other variables. The whole chunk between {{#name}} and {{/name}} is treated as one unit. The fence is asking "if this variable has content, render all of this; otherwise, render none of it."

          The names must match

          • {{#scenario}}…{{/scenario}} — works.
          • {{#scenario}}…{{/Scenario}} — broken (capital S doesn't match).
          • {{#scenario}}…{{/scneario}} — broken (typo).

          When the names don't match, the fence isn't recognized — the literal {{#scenario}} tag stays in the output. Use Preview to spot it.

          How the default template uses them

          The default template wraps every section so empty fields don't show up:

          {{#description}}[Character Description]
{{description}}{{/description}}

{{#personality}}[Character Personality]
{{personality}}{{/personality}}

{{#scenario}}[Scenario]
{{scenario}}{{/scenario}}

          A character with a description and personality but no scenario produces:

          [Character Description]
A wise old wizard.

[Character Personality]
Calm and patient.

          The [Scenario] block silently disappears.

          Random choice — {{random:a,b,c}}

          Picks one of the comma-separated options at random each time the prompt is built.

          The weather is {{random:sunny,rainy,foggy,stormy}}.

          Per-character override

          If a character card has a system_prompt field, that text fills {{system_prompt}}. If you remove the variable from your template, the per-character field has no effect.

          Tips

          • Click Preview (eye icon) any time to see exactly what will be sent for the active character + persona.
          • Click Reset (circular arrow) to return to the default template.
          • Multiple templates can be saved — switch between them with the dropdown.
          • Typos in conditional tags fail silently (e.g. {{#x}}…{{/y}} won't match) — Preview is your debugging aid.

          Sampler reference

          Samplers shape how the model picks its next word. The defaults are sensible — only tweak these if you want to change the feel of the output. Settings marked ADV are niche or experimental.

          Core samplers

          Temperature
          How "wild" the writing is. Low (0.5) = safe and predictable. High (1.3+) = creative but risks nonsense. Most models like 0.7–1.0.
          Dynamic Temp ADV
          Lets temperature flex up or down on the fly based on how confident the model is. Range sets how far it can swing; Exponent shapes the curve. Off when range is 0.
          Top-P (nucleus)
          Only consider the smallest set of words whose combined probability adds up to this fraction. 1.0 = no filtering; 0.9 = drop the long tail of unlikely words. Lower values = safer.
          Top-K
          Only consider this many top candidates each step. 0 = unlimited. 40 is a common middle ground; 1 = always pick the single most-likely word (deterministic).
          Min-P
          Drop any word whose probability is less than this fraction of the top word's. Modern alternative to Top-P that adapts better to the model's confidence. 0.05–0.1 is typical.
          Rep. Penalty
          Discourages the model from repeating tokens it has recently used. 1.0 = off; 1.1–1.15 nudges it to use fresh words. Last N = how far back to look.
          Max Tokens
          Hard cap on how many tokens (~words) the model is allowed to generate in one reply.

          Advanced samplers ADV

          Typical-P
          Picks tokens whose surprisal is close to the average — keeps writing "typical" rather than chasing peaks. 1.0 = off. Try 0.9 for steadier prose.
          Top-N Sigma
          Filters tokens by their distance from the mean (in standard deviations) of the model's logit scores. -1 = off. Newer alternative to Top-P/Min-P.
          TFS-Z (Tail-Free Sampling)
          Trims the long flat tail of low-probability tokens by looking at the curve's second derivative. 1.0 = off. Lower = more aggressive trimming.
          Presence Penalty
          Flat penalty applied once a token has appeared at all. Pushes the model toward new vocabulary. 0 = off.
          Frequency Penalty
          Penalty that grows with how often a token has appeared. Stronger anti-repetition than Presence. 0 = off.
          DRY (Don't Repeat Yourself)
          Penalises the model for echoing recent multi-word phrases verbatim. Good for fighting "looping" replies. Multiplier = strength; Base = exponent; Allowed length = ignore phrases shorter than this.
          Mirostat
          Adaptive controller that targets a specific surprisal level (perplexity) instead of using fixed Top-P/Top-K. Tau = target surprisal; Eta = how fast it adapts. Modes: 0=off, 1=v1, 2=v2.
          XTC (Exclude Top Choices)
          With some probability, throws away the most likely tokens to force less obvious choices — adds creative spark. Probability = how often it triggers; Threshold = how confident those top picks must be before XTC kicks in.
          Seed
          Fixes the random number generator so the same prompt produces the same reply. -1 = random each time. Use a fixed seed when comparing settings.

          Different backends support different samplers — anything your engine doesn't recognise is silently ignored. When in doubt, leave the advanced ones off.
