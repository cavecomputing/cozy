Cozy Database Schema

Every table SQLite actually holds after init_db(), read out of a freshly created cozy_chat.db rather than transcribed. Character cards are not in here — they live on disk as PNGs, and this database only indexes them.

11 tables 3 indexes 12 migrations applied WAL journal mode synchronous = NORMAL foreign_keys = ON per connection

How the rows hang together

Only three foreign keys are declared, and all three cascade. Everything drawn with a dashed line is a reference the application maintains itself — SQLite will not clean it up for you.

Deleting a lorebook clears matching chats.active_lorebook_id in application code, because nothing in the schema will. A deleted persona leaves persona_id pointing nowhere by design — old messages keep the name they were written under.

No column matches that.

Migration ledger

versions 1–12

Ordered, and the order is the point: each runs once, in a serialized transaction, and a shipped entry is never renumbered, renamed or reordered.

  1. 01retire_duplicate_greeting_cleanupBaseline: the old destructive greeting repair is retired, not re-run.
  2. 02delete_legacy_context_max_messagesDrop the retired message-count context limit.
  3. 03add_summary_to_legacy_default_promptAdd summary memory to untouched copies of the old stock prompt.
  4. 04add_narrative_preamble_to_default_promptV2 → V3 preamble, untouched copies only.
  5. 05upgrade_default_prompt_to_v4V3 → V4: prose guidance moves to the post-history template.
  6. 06enforce_house_style_post_historyV1 post-history → the enforced house-style V2.
  7. 07rename_default_prompt_to_nanobearRename "Default" to "NanoBear" — the one migration that matches on name, not content.
  8. 08remove_character_galleryRetire gallery settings, collection tables, and the archive column.
  9. 09backfill_chat_personaSeed chats.persona_id from each chat's own history.
  10. 10delete_summary_compress_batchDrop the retired summary compression setting.
  11. 11delete_default_prompts_seededDrop the retired one-shot flag for prompt seeding.
  12. 12backfill_stock_prompt_descriptionsFill blank descriptions on bundled NanoBear prompts; user-set text untouched.

Migrations 3–7 are the last of their kind. The house prompt now ships as a file and a revision arrives as a new file, so no future release rewrites a prompt row.

Seeded settings

fresh install

What a brand-new cozy_chat.db holds in settings before anyone touches anything. Read straight out of one.

active_system_prompt'2'
context_max_tokens'32768'
show_context_token_meter'1'
show_advanced_configuration'0'
extra_request_params''
summary_api_endpoint''
summary_api_key''
summary_api_model''
summary_cap_pct'10'
summary_trigger_interval'10'
default_characters_seeded'1'
default_regex_seeded'1'

The two *_seeded flags flip whether or not anything was inserted, and are never reset. That is what makes a deleted bundled character or regex preset stay deleted. active_regex_preset is missing on purpose — bundled filters ship inactive.

The database version

currently 12

There is no separate version number. The highest entry in the migration registry is the schema this build understands, and the highest row in a database's ledger is the schema that database is at. pyproject.toml's 0.0.0 is a packaging placeholder and the About page's build string names a Git commit — neither is a schema version.

That number is what a backup carries. GET /api/backup zips the data directory with a cozy-backup.json naming it; POST /api/backup/restore compares it against the registry: lower restores and is migrated up by init_db(), equal restores as-is, higher is refused with 409 — that archive knows migrations this build does not.

Data lives in two places, so a backup has to cover both: this database, and the PNG files in data/characters/ that carry the actual card data. The thumbs/ cache is keyed by image content and rebuilt on demand, so it is left out.
